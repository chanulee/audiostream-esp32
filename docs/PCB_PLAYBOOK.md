# PCB 제작 플레이북 — LOVELACE에서 배운 것

이 문서는 이 저장소의 리뷰 문서, 보관 판(01–09)의 "올린 이유", git 기록, 검사 스크립트, 그리고 실제로 틀렸다가 고친 사례를 모아 정리한 것입니다. 이 프로젝트의 Claude 세션 대화 원문 9개(10-14 ~ 10-28)도 읽고, 문서에 남지 않은 시행착오를 11절에 더했습니다. 2026-10-14 S3 rev A부터 2026-10-19 AS-008 rev A까지 10개 판을 거쳐 첫 주문까지 간 과정에서 나왔습니다.

**전제:** 아직 실물 측정은 없습니다. 아래의 "통과"는 모두 파일·계산·시뮬레이션 기준입니다.

이 내용을 다른 PCB 프로젝트에서도 쓰도록 Claude 스킬 `pcb-prototype-readiness`(`~/.claude/skills/pcb-prototype-readiness/`)로 옮겼습니다.

## 0. 가장 중요한 다섯 가지

1. **DRC 0은 "설계가 맞다"가 아닙니다.** DRC·ERC·parity·Gerber netcheck는 모두 `plan_pcb.py`의 넷리스트를 정답으로 봅니다. 넷리스트가 틀리면 전부 0으로 통과합니다. 그래서 데이터시트에서 직접 쓴 핀표(`pinout_check.py`)가 따로 필요했습니다.
2. **라이브러리 풋프린트의 패드 이름과 치수를 믿지 마세요.** AUX 잭(PJ-320D) 하나에서만 네 번 틀렸습니다(패드 이름 → 접점, 구멍 지름, 패드 폭, 패드 위치, 그리고 단자 기능). 제조사 도면의 모든 치수를 하나씩 대조하고, 핀 기능이 안 적혀 있으면 제조사에 물으세요.
3. **KiCad 좌표·회전을 JLC에 그대로 보내면 안 됩니다.** 같은 패키지라도 0° 방향이 달라서, 그대로 보냈으면 IC 4개가 돌고 탄탈 극성이 뒤집혔을 겁니다.
4. **도구 하나만 쓰면 반드시 놓칩니다.** 도구마다 보는 범위가 다르고, 외부 도구는 파서 버그·과민 규칙·거짓 양성이 많습니다. 각 도구가 *무엇을 못 보는지*를 알고 겹쳐 써야 합니다(3절 표).
5. **주문 전 구리가 바뀌면 새 번호.** 같은 이름의 Gerber가 두 벌 생기면 어떤 파일을 주문했는지 추적이 안 됩니다.

## 1. 파이프라인 (스크립트로 처음부터 끝까지)

보드는 손으로 그리지 않고 스크립트로 매번 다시 만듭니다. `hardware/lovelace-as-008/make_board.sh` 한 번이면 아래가 순서대로 돌고, 하나라도 실패하면 release를 만들기 전에 멈춥니다.

| 단계 | 스크립트 | 하는 일 | 실패 시 |
|---|---|---|---|
| 1 | `plan_pcb.py` | 넷리스트, 부품 값·LCSC 번호, 큰 부품 수동 배치, 검사 규칙(near/apart) → `placement.json`, `design.json` | — |
| 2 | (선택) `autoplace.py` | 나머지 수동부품을 annealing으로 배치 (`make_board.sh anneal <seed>`) | — |
| 3 | `placement_check.py` (pcb-layout-skill) | 간격·가장자리·keep-out·near/apart 규칙 | ERROR가 있으면 좌표 바꾸기 전에 멈춤 |
| 4 | `pinout_check.py` | **데이터시트에서 손으로 쓴** 핀·수동부품 계약표와 넷리스트 대조 (142 → 305 항목) | exit 1 |
| 5 | `sim/power_path.py` | ngspice 전원 경로 모델 (기동, 펄스 부하, 홀드업 16조건) | FAIL exit 1, 미완료 UNVERIFIED exit 2 |
| 6 | `build_pcb.py` | 보드·회로도·BOM·CPL·DSN 생성, 손 배선(USB, 버크 SW, eFuse 핀, DAC 홀드업 레일), 고정 UUID, DNP 처리 | — |
| 7 | `jlc_check.py` | EasyEDA/JLC 풋프린트를 받아 핀 번호로 맞춰 **JLC 기준 회전·원점**으로 `cpl.csv` 작성, 극성·재고 확인 | 불일치 시 exit 1 |
| 8 | KiCadRoutingTools 3단계 | 오디오 → 전원 → 나머지 (2절) | — |
| 9 | `finish_pcb.py` | 쓰지 않은 via 정리, 바닥 테스트 패드, 평면 채움 | — |
| 10 | `kicad-cli drc --schematic-parity --exit-code-violations`, `erc --exit-code-violations` | 위반이 있으면 종료 코드로 멈춤 | release 단계 도달 안 함 |
| 11 | `audit_pcb.py` | 좌표·핀넷 readback, 디커플링 패드 거리, 라이브러리 패드 형상, AUX 접점 순서, 윗면 패드 안 via, 실크 버전 문구, 부품값·DNP | assert로 멈춤 |
| 12 | Gerber/drill/IPC-D-356 export → `audit_release.py`, `gerber_check.py netcheck`, `render` | 파일 구성, Gerber ↔ IPC 연결성(쇼트·단선), 실크-마스크 겹침, 구리-가장자리 | — |
| 13 | ZIP, `rendering/render_board.py` | 주문 ZIP, 3D·층별·배선 렌더, 이전 빌드와 차이 | — |

**팁**
- 실크만 바꿀 때는 `make_board.sh release`로 배치·구리를 그대로 두고 DRC부터 다시 돕니다(웹 편집기·Figma 플러그인 공통).
- DRC 위반이 정말 release를 막는지 일부러 트랙을 0.3mm 옮겨 실행해 확인했습니다(종료 코드 5). **검사가 실패할 때 실제로 멈추는지도 검사해야 합니다.**
- 같은 입력이면 같은 구리가 나오게 만들었습니다(고정 UUID, 결정적 라우터). 그래야 "재빌드했더니 Gerber가 다르다"를 진짜 변경과 구분할 수 있습니다.

## 2. 배치·배선 노하우

### 보드 크기와 배치
- **사용자 요구:** 최대한 작게, USB-C와 AUX를 한 변에. S3 80×60 → AS-001 55×55 → AS-002 rev B 35×50 → rev C 이후 37×41mm(1,517mm²). 점유율 76%에서는 더 줄일 여지가 거의 없고, 남은 방법은 CH340N·USBLC6를 빼는 것뿐이라 첫 보드 전에는 하지 않았습니다.
- **모듈 안테나는 보드 밖으로.** WROVER-E는 Espressif 배치 1안대로 안테나 영역 6.22mm를 통째로 보드 밖에 두고, 모듈 아래·안테나 띠에 via/배선을 금지했습니다. 금속 나사는 안테나에서 멀리(11mm) 두고 나일론 나사를 권장합니다.
- **디커플링은 "패드 사이 거리"로 검사합니다.** 부품 중심 거리 말고 커패시터 패드 가장자리 ↔ IC 핀 패드 가장자리 거리 목표를 정해 19개를 `audit_pcb.py`가 매번 잽니다.
- **버크 입력 루프는 짧게.** C4가 U3 VIN·PGND에서 약 3mm라 루프가 3×2mm입니다. 동작엔 문제없지만 다음 판에서 핀 바로 옆으로 붙일 후보입니다.

### 층 구성 (4층)
- L1 부품 + 신호 + GND pour, **L2 GND 전면(신호 없음)**, L3 +3V3_D 전면, L4 신호 + GND pour.
- **오디오 넷은 F.Cu에만** 둡니다. 바로 아래가 L2 GND라서입니다. B.Cu로 내려가면 L3 디지털 전원 평면 위를 지나게 됩니다.
- 기준 평면 연속성은 배선을 0.1mm 간격으로 샘플링해 아래 평면이 끊기는지 검사했습니다(끊김 0).

### 라우터 (KiCadRoutingTools v0.23.0 기본, FreeRouting은 비교용)
- **3단계로 나눠 돌립니다.** ① 오디오 넷을 F.Cu에만, via 없이 ② 전원을 0.3mm 고정(넥다운·축소 금지) ③ 나머지 0.2mm(필요하면 보드 최소 0.15mm까지).
- **오디오 배선은 1단계 직후 잠급니다.** 안 잠그면 2·3단계가 막혔을 때 오디오 배선을 뜯어 B.Cu로 옮깁니다.
- **KRT는 출력 파일 옆 `.kicad_pro`를 다시 써서 다음 단계의 DRC 기준으로 읽습니다.** pcbnew로 저장하면 그 파일의 넷클래스 패턴이 지워지므로, 잠금 저장 전에 복사해 두고 되돌립니다. 그리고 매번 빈 폴더에 출력합니다.
- **라우터가 SMD 패드 안에 via를 넣습니다.** 같은 넷이라 KiCad DRC는 잡지 못합니다. AS-003에서 패드 안 4개 + 가장자리에 걸친 6개를 찾았습니다(R17·R10·U4·U1 등). 리플로 때 땜납이 구멍으로 빠져 접합 불량·툼스톤이 생길 수 있습니다. 대책: `--same-net-pad-clearance 0.1` + `audit_pcb.py`의 "윗면 SMD 패드에 닿는 via" 검사(빌드 중단). 이 수정이 배선만 바꾼 변경이라도 AS-004로 번호를 올렸습니다.
- **라우터가 못 빠져나오는 핀은 손으로 그립니다.** 2×2mm QFN 가운데 핀(eFuse OVLO·ILIM·ITIMER), USB D+/D−, 버크 SW, DAC 홀드업 레일은 `build_pcb.py`에서 직접 그립니다.
- FreeRouting은 실행마다 결과가 달랐고, 같은 배치에서 KRT가 길이(442 → 403mm), 짧은 조각(53 → 9), 전원 넥다운(14mm → 0), 오디오 B.Cu via(6 → 0) 모두 나았습니다.

### 비아·트랙
- 일반 via 0.6/0.3mm. USB D− via는 처음 0.4/0.2mm였는데 JLC 다층 표준 최소 지름이 0.45mm라 AS-008에서 0.45/0.2mm로 올렸습니다(annular ring 0.125mm).
- 전원 폭은 `pcbcalc.py`로 계산합니다. 예: VBUS 0.75A·+10°C·1oz 외층 → 0.211mm 필요, 실제 0.3mm 이상.
- 버크 SW는 0.6mm, 패드 진입부만 0.25mm.

## 4. 부품·풋프린트 — 사례로 배운 것

### AUX 잭 PJ-320D (C431535): 한 부품에서 다섯 번
| 판 | 무엇이 틀렸나 | 어떻게 알았나 |
|---|---|---|
| AS-002 rev C → AS-003 | KiCad 패드 이름(T/R1/R2/S)을 접점으로 믿음 → Tip이 접지되고 R이 슬리브와 쇼트 | 도면의 접점 깊이로 재해석 |
| AS-004 → AS-005 | 위치 결정 구멍 Ø1.5mm(도면 Ø1.0, 핀 Ø0.75), 패드 폭 1.2mm(도면 1.5) — KiCad 기본 풋프린트 그대로 | 독립 재검수에서 도면과 대조 |
| AS-005 → AS-006 | 잭 축에서 패드까지 2.0–4.5mm(도면 3.05–4.65mm, 몸체 바깥). 1mm가 몸체 아래, 단자 끝은 패드 밖 → 필렛 없음 | 도면 PNG를 잘라 픽셀로 재서 대조. 앞 검수는 지름·폭만 봄 |
| AS-005 → AS-006 | CPL을 패드 평균으로 맞춰 JLC 위치 결정 핀이 구멍에서 0.125mm 어긋남(여유가 정확히 0.125mm) | JLC 풋프린트의 HOLE 좌표를 같은 변환으로 대입 |
| AS-006 → AS-007 | 단자 위치 = 접점 위치라는 가정 자체가 틀림. 실제는 A=Tip, D=Ring1, C=Ring2, B=Sleeve → 오른쪽 채널이 접지됨 | LCSC 엔지니어 회신 + 도면 회로도(OA–OD) 순서 |

**교훈**
- 도면에 단자 문자만 있고 기능이 없으면 **추정하지 말고 제조사·공급사에 물어봅니다.** LCSC 지원(support@lcsc.com)이 제조사 엔지니어 답을 하루 안에 받아 줬습니다.
- 도면 대조는 **모든 치수**를 합니다. 지름·폭만 맞추고 위치를 안 보면 또 틀립니다.
- 패드는 도면 랜드를 덮고 양 끝에 0.2mm 여유를 두되, 가장자리 구리 간격(0.4mm)과 옆 부품 간격(0.5mm)이 허락하는 만큼만 늘립니다. 그 결과 J2를 0.3mm 옮겼습니다.
- 위치 결정 핀이 있는 부품은 CPL을 **핀 기준**으로 계산하고, 어긋남(0.05mm 이하)을 빌드에서 검사합니다(`jlc_check.py`의 PEGGED).
- 검사도 같이 바꿉니다: `audit_pcb.py`는 이름이 아니라 개구부에서의 거리 순서로 접점을 검사하고, `pinout_check.py`에 J2 항목을 넣었습니다.
- 그래도 **주문 전에 잭 2–3개를 사서 플러그를 꽂고 멀티미터로 재는 것**이 가장 확실합니다.

### CPL 회전 (가장 치명적이었던 것)
KiCad 회전을 그대로 쓰면 U2 PCM5102A 180→90, U4 LDO 0→180, U5 USBLC6 0→270, U7 CH340N 0→270, C25 탄탈 90→270이 됩니다. `jlc_check.py`는 EasyEDA API(`easyeda.com/api/products/<LCSC>/components`)로 JLC 풋프린트를 받아 **핀 번호로 맞춰** 회전과 원점을 계산합니다. 53/53 부품, IC 오차 0.05mm 이하. 그래도 주문 화면 미리보기에서 1번 핀·극성을 다시 봅니다(BRINGUP 1-4 표).

### 극성 부품
- **"1번 핀"의 뜻이 제조사와 JLC에서 다를 수 있습니다.** KENTO KT-0603G LED 사양서는 ①을 +(애노드)로 그리는데, JLC 풋프린트는 1번 패드를 K(캐소드)로 둡니다. 번호 체계가 반대라 공급사 확인을 요청했습니다.
- **LED 밝기:** Vf가 5mA에서 2.6–3.1V라 3.3V·220Ω이면 1–3mA. 어둡지만 표시용으로는 됩니다.

### 정격·감액
- **폴리머 탄탈 감액:** KEMET 기준 10V 이하 부품은 85°C까지 정격의 90%(6.3V → 5.67V). C25는 정상 USB(최대 5.5V)에서 약 5.25V로 안이고, 규격 밖 5.92–6.0V 입력에서만 약간 넘습니다. LCSC 상품 페이지의 데이터시트 링크가 **다른 회사 부품(AVX TAJ) 문서**였습니다 — 링크도 확인하세요.
- **eFuse 형태 확인:** TPS259470A는 *전류 제한형*(ILIM에서 전류를 묶음)이고 TPS259474x가 *차단형*입니다. 같은 데이터시트 안에서도 변형마다 ITIMER 동작이 다르므로 변형 표(Device Comparison)를 먼저 봅니다.
- **"USB 500mA를 넘으면 안 되지 않나?"** eFuse ILIM은 평소 소비 전류가 아니라 이상 시 상한입니다. 이미 0.56–0.75A였습니다.
- **인덕터 정격 두 가지를 섞지 마세요:** DFE201612P-2R2M은 인덕턴스 30% 감소 기준 2.1A, 온도 상승 40°C 기준 1.5A입니다. 한때 둘을 바꿔 적었습니다.
- **ESP32 피크 전류:** "외부 전원은 0.5A 이상 공급"은 공급 능력 권장값이지 부하가 아닙니다. 부하 계산에는 표 16의 모듈 피크(350mA)를 씁니다.

### 데이터시트 구하기
- LCSC 데이터시트 링크는 curl에 HTML만 돌려줍니다. 브라우저로 열면 iframe이 `datasheet.lcsc.com/datasheet/pdf/<hash>.pdf`를 불러오고, 그 주소는 바로 받아집니다.
- EasyEDA 3D 모델: `modules.easyeda.com/3dmodel/<uuid>`는 OBJ, `modules.easyeda.com/qAxj6KHrDKw4blvCG8QJPs7Y/<uuid>`가 STEP입니다(User-Agent 필요).
- TI 데이터시트는 `ti.com/lit/ds/symlink/<part>.pdf`, `pdftotext -layout`으로 핀표·식을 뽑아 grep합니다.

### 미실장(DNP) 자리
- 첫 보드에서 결과에 따라 달 수 있게 빈 자리를 둡니다(C26: eFuse ITIMER, 1–10nF면 짧은 피크가 nF당 약 0.8ms 통과).
- **KiCad DNP 표시는 페이스트 Gerber에서 패드를 빼지 않습니다.** 빈 패드에 땜납이 찍히면 0402 두 패드가 이어질 수도 있으므로 `build_pcb.py`가 DNP 패드의 F.Paste를 직접 지웁니다. BOM·CPL에서도 빠지는지 확인합니다.

## 5. JLC 주문 데이터와 조립

- **BOM에는 모든 줄에 실제 LCSC 번호.** 범용 "10k 0402" 사양만 적으면 주문이 안 됩니다. 재고는 `jlc_check.py`가 JLC API(`selectSmtComponentList`)로 매번 조회하고, 결제 직전에 다시 봅니다(조회는 예약이 아님).
- **Extended 부품 수수료는 종류당, 주문당**(약 3달러). ESP32가 Extended라고 다른 게 공짜가 되지 않습니다. 이 보드는 19종이라 주문마다 약 57달러. 재주문도 새 주문으로 계산됩니다 — 고정비 때문에 2장과 5장의 총액 차이가 작습니다.
- **PCB는 5장 이상 만들고 일부만 조립**할 수 있습니다. 남은 맨 기판의 부품은 직접 사야 하고, 0402·2×2mm QFN이 많아 손 조립은 어렵습니다.
- **조립 레일은 왼쪽·오른쪽만, 폭 5mm 이상, mouse-bite.** 위로 안테나 6.2mm, 아래로 J2 약 2.3mm·J1 0.5mm가 나와 위아래 레일은 부품과 겹칩니다. 오른쪽 가장자리 부품(C15 0.97mm, D3 0.55mm) 때문에 V-cut은 피합니다.
- **JLC가 확인 메일을 보냅니다.** U1 방향 확인 요청이 왔고, 파일의 1번 핀 좌표·CPL 회전과 대조해 답했습니다. JLC 3D 미리보기는 WROVER-E 자리에 WROVER-IE 모델(IPEX 커넥터)을 그리지만 패드는 같습니다.
- **주문 파일 고정:** 주문한 ZIP·BOM·CPL의 SHA-256을 `REVIEW_NETLIST.md` 0절에 적고, 주문한 커밋을 남깁니다(태그 `hw/<board>-rev<X>`).

## 6. 3D 모델·렌더

- KiCad에 HRO TYPE-C-31-M-12, PJ-320D, WROVER-E STEP이 없어 EasyEDA STEP을 `lib/3d/`에 넣었습니다.
- **EasyEDA의 `c_origin`·`z` 값으로 계산한 오프셋은 틀렸습니다.** J2는 축 방향 4.6mm, 다음엔 0.94mm, 높이 3mm가 어긋났고, J1은 1.5mm 안쪽·0.85mm 아래였습니다.
- **맞추는 기준은 구리입니다.** 위치 결정 핀이 NPTH 구멍 중심에 오는지(바닥 렌더), 고정 다리가 슬롯 안에 있는지, 셸 앞면이 풋프린트 외형선에 맞는지, 몸체 높이가 도면과 같은지(정면 렌더) 봅니다. 단자를 눈으로 패드에 맞추면 1mm쯤 쉽게 틀립니다.
- KiCad 라이브러리 풋프린트(J1)는 빌드할 때마다 새로 복사되므로 모델 지정은 풋프린트 파일이 아니라 `build_pcb.py`에서 합니다.
- 3D 모델 수정은 Gerber에 영향이 없습니다. 그래서 새 AS 번호를 올리지 않았습니다.
- 렌더링 도구(`rendering/`)는 Python 3.10–3.13이 필요합니다(cadquery-ocp). macOS 기본 python3이 3.14면 `run.sh`가 맞는 버전을 찾습니다. 브라우저 창이 숨겨져 있으면 WebGL이 꺼집니다.

## 7. 재현성·버전 관리

- **번호 규칙:** 주문 전 구리 변경(넷리스트·외곽·배선만이라도) = 새 AS-<n>. 주문 후 = rev A/B. 3D 모델·문서·실크만 바뀌면 번호를 올리지 않습니다(실크는 `release`로 재생성).
- **번호의 유일한 출처는 `plan_pcb.py`의 `BOARD_ID`, `BOARD_REV`.** 실크 문구는 `silkscreen.json`에 따로 있어 같이 바꿔야 하고, `audit_pcb.py`가 빠뜨리면 멈춥니다.
- **새 판을 시작할 때:** 현재 폴더를 `hardware/archive/NN-<이름>/`에 복사(보드·회로도·ZIP·문서·렌더) → 폴더와 `lovelace-as-<n>.*` 파일 이름 변경 → `BOARD_ID` 올림 → `versions.json` 항목 → 보관 README에 "올린 이유"와 해시.
- **Gerber 비교법:** 다시 만들면 생성 날짜·조리개(aperture) 번호·구리 채움 다각형의 중복 꼭짓점이 달라집니다. 줄을 정렬하고 `G04`, `%TF`, `%ADD`, `D<n>*` 줄을 빼고 비교해야 실제 구리 변화만 남습니다. 보드 파일끼리는 트랙·via·패드·존 집합을 KiCad Python으로 비교합니다.
- **해시로 판정:** "검사 통과"는 그 파일의 SHA-256과 함께 적어 둡니다. 다른 장비에서 작업하면 pull 후 해시부터 확인합니다.
- **다른 장비 작업 합치기:** 원격 커밋이 폴더를 옮기면서 새 폴더(`rendering/`)를 커밋하지 않은 일이 있었습니다. 합치기 전에 커밋 안의 파일 목록을 보고, `make_board.sh`가 부르는 경로가 실제로 있는지 확인합니다.

## 8. 펌웨어와 맞물린 하드웨어 함정

- **DAC 뮤트 핀:** PCM5102A XSMT를 3.3V에 묶으면 팝을 막을 수 없습니다. GPIO22 + 10k 풀다운(기본 뮤트)으로 바꾸고, 펌웨어가 I2S 20ms 뒤 해제, 클럭 변경 전 다시 뮤트합니다. 이 핀을 모르는 옛 펌웨어(0.2.x)로는 소리가 안 납니다.
- **`pdMS_TO_TICKS(5)`는 100Hz tick에서 0입니다.** 5ms 뮤트 대기가 실제로는 0이었습니다. 짧은 대기는 `esp_rom_delay_us`로, 긴 대기는 올림 계산으로.
- **CH340N에는 DTR이 없어** 자동 다운로드가 안 됩니다. 버튼(IO0)을 누른 채 USB를 꽂습니다. 버튼을 누른 채 소프트웨어 재시작하면 다운로드 모드로 들어갑니다.
- **USB가 안 될 때 대비:** 바닥 TX/RX/EN/IO0 테스트 패드로 외부 USB-UART를 연결해 첫 펌웨어를 올리고, 이후엔 OTA.
- **스트래핑 핀**(IO2·IO12·IO15·IO5)은 연결하지 않아 내부 풀 기본값으로 둡니다. MTDI가 high면 1.8V 플래시가 됩니다.

## 9. 전원·아날로그 설계에서 배운 것

- **USB-C 전원:** CC1/CC2에 5.1k Rd만 두면 PD 고전압을 요청하지 않으므로 "25W 충전기"도 5V만 줍니다. 잘못된 케이블·전원 대비로 OVLO eFuse(TPS259470A)를 넣었습니다(OVLO 5.63–6.00V, UVLO 4.13–4.39V, ILIM 0.56–0.75A). 분압 저항은 1%·0.1%로 오차 창을 계산합니다.
- **USB 분리 팝 대책:** DAC 전원을 LDO로 분리하고 쇼트키 D5 + 220µF C25로 홀드업. ESP32가 먼저 꺼져 I2S 클럭이 멈추면 DAC가 클럭 정지 소프트 뮤트(3ms)를 끝낼 시간을 줍니다. 명목 계산은 9.6ms였지만 **부품 공차(C25 −20%, DAC 45mA, 4.4V 입력)를 넣으면 3.441ms**로 줄어 기준과 0.441ms 차이였습니다. 명목값만으로 "5–10ms 버팀"이라고 쓰면 안 됩니다.
- **판정 기준을 섞지 마세요:** PCM5102A의 XSMT 뮤트(150 샘플 + 0.2ms)와 클럭 정지 뮤트(3ms)는 다른 경로입니다. 판정 전압도 3.2V/3.0V가 아니라 DVDD/CPVDD 하한 3.1V로 통일했습니다.
- **시뮬레이션 결과에는 세 가지 상태:** PASS, FAIL(exit 1), **UNVERIFIED(exit 2, 해석 미완료·측정값 누락)**. "exit 0이면 통과"로 처리하지 않습니다. 과부하 탐색은 STRESS_ONLY로 따로 보관합니다.
- **USB GND 잡음:** Wi-Fi 송신 펄스(약 0.3A)가 USB 케이블 GND 저항을 지나면 수십 mV가 흔들려, PC USB + 접지된 앰프에서 "지직" 소리가 날 수 있습니다. 첫 보드에서 충전기와 PC를 비교합니다.
- **고칠 수단을 미리 준비:** brownout이면 C26 1nF → 10nF → R15 4.3k 순서. 재작업 부품을 같이 주문합니다.

## 11. 세션 대화에서만 나온 교훈

문서에는 결론만 남고, 대화에는 왜 틀렸는지가 남아 있었습니다. 세션별로 다시 읽어 정리했습니다.

### 11-1. "검사를 돌렸다"와 "검사가 막는다"는 다릅니다
- **DRC가 실패해도 release ZIP이 만들어지고 있었습니다(10-15).** `kicad-cli drc ... | grep Found`는 위반이 있어도 성공으로 끝납니다. `--exit-code-violations` + `set -o pipefail`을 넣고, 일부러 트랙을 옮겨 종료 코드 5로 멈추는 것까지 확인했습니다. 외부 검사 스크립트를 `| tail`로 넘길 때도 그 스크립트가 실패 시 0이 아닌 값으로 끝나는지 확인해야 합니다.
- **`set -e` 스크립트의 마지막 줄 `[ cond ] && cmd`는** 조건이 거짓이면 스크립트 전체를 exit 1로 끝냅니다. if/fi로 씁니다.
- **"메모만 남긴 것"과 "실제로 돌린 것"을 구분해 보고합니다.** 사용자가 "그래서 테스트 다 해본 거야, 메모만 남긴 거야?"라고 되물은 적이 있습니다. 돌리지 않은 항목은 돌리지 않았다고 쓰고, 돌릴 수 있으면 돌립니다.
- **검사기도 오류를 주입해 검사합니다.** UART 교차, FMT 오배선을 복사본에 넣어 `pinout_check.py`가 실패하는지 봤고, 나중에 외부 검토에서 수동부품 4종을 놓친다는 사실이 같은 방법으로 드러났습니다.

### 11-2. 새 기능을 들일 때 결과물 목록 전체를 다시 봅니다
- **DNP를 처음 넣었을 때(10-18) 페이스트를 빠뜨린 이유:** BOM·CPL·회로도 DNP 표시·풋프린트 속성만 떠올렸고, 그 넷만 비교했습니다. "KiCad가 DNP를 페이스트에 반영한다"는 가정을 검증하지 않았고, 어떤 검사도 "CPL에 없는 부품 자리에 페이스트가 있다"를 보지 않습니다. AS-008에서는 Gerber 분석도 다시 돌리지 않았습니다. 판 사이에 **층별 Gerber 개구부 수(페이스트 220 vs 218 등)를 비교**했다면 바로 보였습니다.
- **검사 대상과 주문 대상이 달라질 수 있습니다(10-15).** 실크 편집기로 보드 파일이 바뀌었는데 release ZIP은 몇 시간 전 것이었습니다. 주문 전에 반드시 release를 다시 만들고 해시를 기록합니다("동결").
- **라이브러리 풋프린트를 고쳐도 반영되지 않을 수 있습니다(10-16).** `build_pcb.py`가 KiCad 기본 풋프린트를 매 빌드마다 다시 복사해서, 수정한 J2가 보드에 들어가지 않았습니다. 고칠 풋프린트는 프로젝트 소유 라이브러리(`LOVELACE.pretty`)로 옮깁니다. 패드를 넓히면 그 풋프린트의 실크도 패드와 겹치지 않게 다시 잘라야 합니다.

### 11-3. 부품 선정
- **작은 모듈의 함정:** Seeed XIAO(ESP32-C3/S3/C6)에는 Bluetooth Classic이 없어 A2DP를 받을 수 없습니다. 가장 작은 후보 ESP32-PICO-MINI-02(13×17mm)는 PSRAM이 2MB라 탈락. 기능 요구(BT Classic, PSRAM 8MB)를 먼저 고정하고 크기를 봅니다.
- **커넥터는 JLC 재고가 많은 SMD 부품으로:** THT 잭(CUI SJ1-3523N) → PJ-320D(C431535). 대신 위 4절처럼 도면 검증 비용이 들었습니다.
- **OVLO를 너무 낮게 잡으면 정상 충전기에서 끊깁니다(10-14).** 처음 5.38V(5.29–5.49V)는 USB-C 상한 5.5V 근처라 위험해서 5.80V로 올렸습니다. 분압 저항 공차·임계값 오차·누설을 넣은 최악 범위(5.63–6.00V)로 판단합니다.
- **재고 없는 정밀 부품:** 383k 0.1%가 품절이라 1%를 쓰고 범위를 다시 계산했습니다. EasyEDA에 데이터가 없는 부품(C5126206)은 검증이 안 되므로 같은 사양의 다른 부품(Yageo C163468)으로 바꿨습니다.
- **배선을 줄이는 핀 배정:** I2S 핀을 DAC 핀 순서에 맞춰 다시 배정해 교차를 없애고 직렬 저항 3개를 뺐습니다(5mm 배선은 1ns 에지 기준 임계 길이 약 25mm보다 훨씬 짧음). 핀을 바꾸면 펌웨어 sdkconfig도 같이 바꿉니다.
- **인덕터:** TI 방식(최대 부하 1A 기준 피크 1.19A + 20% = 1.43A)으로 포화 정격과 비교합니다. 단락 시 전류 제한(최대 2.45A)까지는 요구하지 않습니다.

### 11-4. 툴체인 함정
- **FreeRouting 2.5.0은 Java 25가 필요합니다**(21로는 안 됨). 휴대용 JRE를 `work/tools/`에 둡니다. 실행마다 결과가 다르고 "pre-existing violations" 목록도 매번 바뀝니다. 오래된 `.ses`를 불러오면 이전 배치의 트랙이 들어와 오류가 납니다.
- **스크립트로 DSN을 내보내면 프로젝트 넷클래스가 빠집니다.** DSN의 class 블록을 직접 고쳤습니다(괄호 짝 주의).
- **KiCadRoutingTools:** 원본은 drandyhaas 저장소(atomic14 포크는 오래됨). 로컬 빌드 dylib가 이 macOS에서 로드되지 않아 미리 빌드된 바이너리를 씁니다. 막히면 **스스로 간격을 0.1mm, 폭을 0.089mm까지 줄입니다** → `--escalation`을 꺼서 보드 규칙 아래로 못 내려가게 합니다. 0.06mm 미만의 끊긴 조각을 남기므로 `finish_pcb.py`가 지웁니다.
- **결정성:** 같은 입력에서 해시가 달라지던 원인은 부품 내부 UUID였습니다. UUID를 고정하고, 두 번 돌려 구리 항목(370개) 차이 0을 확인했습니다.
- **pcbnew API:** 보드에 추가하기 전에 풋프린트를 `Flip`하면 KiCad가 segfault로 죽습니다. 먼저 `Add`, 그다음 `Flip`.
- **EasyEDA API는 요청이 몰리면 403**을 줍니다. 재시도 간격(5/20/60초)과 요청 사이 1초를 둡니다. 결과는 `work/easyeda-cache/`에 캐시합니다.
- **ngspice 모델의 첫 실패가 모델 결함일 수 있습니다.** eFuse UVLO 히스테리시스(4.26/3.87V)를 빠뜨려 4.4V 입력에서 무너지는 결과가 나왔고, 데이터시트대로 넣자 사라졌습니다.
- **sdkconfig 캐시:** 기본값(`MUTE_GPIO=22`)을 바꿔도 캐시된 sdkconfig에는 옛 값(−1)이 남습니다. 백업 후 재생성하고 차이가 의도한 한 줄뿐인지 비교합니다. 환경 이름을 바꾸면 새 sdkconfig가 만들어집니다.
- **git:** 남은 0바이트 `.git/index.lock`은 실행 중인 git 프로세스가 없는지 확인한 뒤 지웁니다. 정체를 모르는 미추적 폴더(`renders/requested/`)는 커밋하지도 지우지도 않고 묻습니다.
- **버전을 덮어쓰기 전에 보관합니다.** AS-002 rev B는 같은 폴더에서 rev C로 고쳐 나가느라 원본이 사라지고 이미지 두 장만 남았습니다.

### 11-5. 실크스크린 (웹 편집기, Figma 플러그인)
- **JLC 최소:** 실크 선폭 0.15mm, 글자 높이 1mm. Figma에서 외곽선으로 만든 글자는 0.10–0.125mm가 흔해서, 저장 때 0.14mm 미만을 0.175mm로 자동으로 굵게 합니다(**변경 여부와 관계없이 매번 전체 검사**, 바뀐 것만 보다가 7개를 놓쳤습니다). 굵게 한 결과는 Figma에도 다시 그려 미리 보여 줍니다.
- **TEXT 레이어의 글꼴은 무시됩니다.** KiCad 텍스트는 항상 KiCad 기본 스트로크 글꼴로 인쇄됩니다. 글꼴을 지키려면 외곽선으로 만들고, **보드 버전 문구는 TEXT로 남깁니다**(audit가 텍스트로 찾음).
- **Figma 함정:** 내보내기 크기를 0.1mm로 반올림해서 10배로 내보냅니다. 플러그인 manifest는 IP 주소를 받지 않아 `localhost`를 쓰고, `localhost`가 IPv6로 풀릴 수 있어 브리지는 IPv4·IPv6 둘 다 듣습니다. 네임스페이스 접두사(`<ns0:svg>`)가 붙은 SVG는 Figma가 읽지 못합니다. 실크 항목은 보드당 100개 제한이 있어 글자를 그룹으로 묶습니다.
- **"100% 반영됐다"고 말하기 전에 픽셀 비교:** 모듈 내부를 빼고 비교해서 반영 안 된 변경을 반영됐다고 보고한 적이 있습니다. 앞·뒷면을 모듈 내부까지 포함해 80px/mm로 렌더해 빠진 면적·남는 면적을 잽니다.
- **실크만 바꾸는 저장은 구리를 건드리지 않아야 합니다.** 실크 편집 후 `make_board.sh release`를 돌려 구리·마스크·드릴·CPL이 바이트 단위로 같은지 확인했습니다.
- **KiCad 3D 렌더는 페이스트를 회색으로 그립니다.** 주문 결과(ENIG 금색)와 다르게 보이면 렌더에서 페이스트를 빼고 봅니다.
- **저장할 때 KiCad에서 그 프로젝트를 닫아 둡니다.**

### 11-6. 사용자와 일하는 방식에서 배운 것
- **번호·라이선스·공개 여부처럼 되돌리기 어려운 결정은 사용자에게 묻습니다.** 배선만 바뀐 수정을 같은 번호로 두자고 했다가 AS-004로 올렸고, 공개 저장소에 MIT 라이선스를 임의로 붙였다가 되돌렸습니다(30분 공개된 MIT는 철회할 수 없음).
- **사용자가 만든 결과를 존중하되 확인합니다.** 다른 장비에서 푸시한 커밋이 `rendering/` 폴더를 빠뜨려 `make_board.sh`가 깨질 뻔했습니다. 합치기 전에 커밋 안의 파일과 스크립트 경로를 확인합니다.
- **외부 리뷰 의견은 "반영할 것은 반영하고, 아닌 것은 근거와 함께 거른다".** 예: TPS62162 PSpice 시뮬레이션 제안은 기생 성분을 못 본다는 이유로 첫 보드 실측으로 대체했고, 인덕터 포화 지적은 TI 계산법으로 반박했습니다.
- **목표를 먼저 고정합니다.** "1순위는 주문했을 때 작동하는 것"을 기준으로 위험을 순서 매기고(실장 방향 → 잭 배정 → 납땜 → 브라운아웃 → USB), 주문을 막는 일과 기다리는 동안 할 일을 나눴습니다.
- **오실로스코프가 없을 때의 측정 계획:** 전압 표시 USB 케이블, 멀티미터, 웹 UI의 `reset_reason`·`uptime_s`, 시리얼 로그로 판정하도록 BRINGUP을 다시 썼습니다. 측정 장비부터 물어봅니다.
