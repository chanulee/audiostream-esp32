# AS-008 rev A 주문과 첫 보드 확인 절차

아직 실물로 확인한 항목은 없습니다. 아래 값은 데이터시트 기준 예상치이며, 측정값을 옆에 적어 두면 REVIEW.md의 미확인 항목을 하나씩 지울 수 있습니다.

## 1. JLCPCB 주문

1. `./make_board.sh`를 실행합니다. 끝까지 통과하면 `lovelace-as-008-revA-release.zip`(Gerber, drill), `bom.csv`, `cpl.csv`가 최신입니다. DRC·ERC 위반, JLC 부품 대조 실패, 감사 실패가 있으면 스크립트가 중간에 멈춥니다.
2. PCB: 4층, 1.6mm, 37 × 41mm. 임피던스 제어는 필요 없습니다(USB 2.0 Full Speed와 I2S 몇 mm).
3. PCBA: 윗면만 조립합니다. 바닥면에는 부품이 없고, 테스트 패드 11개만 있습니다(BOM·CPL에 없음).
4. **배치 미리보기에서 방향을 꼭 확인하세요.** `cpl.csv`는 `jlc_check.py`가 JLC 풋프린트 기준으로 회전과 원점을 다시 계산한 값입니다. KiCad 값을 그대로 쓰면 다음 부품이 돌아갑니다.

   | 부품 | KiCad 회전 | CPL(JLC) 회전 | 확인할 것 |
   |---|---:|---:|---|
   | U2 PCM5102A | 180 | 90 | 1번 핀 점이 오른쪽 아래(C12 쪽) |
   | U4 TPS7A2033 | 0 | 180 | 1번 핀(IN)이 C8 쪽 위 |
   | U5 USBLC6 | 0 | 270 | 1번 핀이 왼쪽 위 |
   | U7 CH340N | 0 | 270 | 1번 핀이 왼쪽 위(U5 쪽) |
   | C25 220µF 탄탈 | 90 | 270 | + 표시(띠)가 아래쪽(DAC 쪽) |
   | D5 RB551V | 270 | 270 | 캐소드 띠가 위쪽(5VD 쪽) |
   | D4 LED | 0 | 0 | 캐소드가 왼쪽(모듈 쪽) |

   J2(AUX 잭)는 회전보다 위치를 봅니다. 잭 바닥의 위치 결정 핀 2개가 보드 구멍 2개 위에 있어야 합니다. `cpl.csv`는 핀 기준이며, 핀과 구멍의 여유는 0.125mm뿐입니다.

   `renders/latest/assembly-top.png`의 빨간 점이 1번 핀, K는 캐소드, +는 탄탈의 +입니다. 미리보기와 하나라도 다르면 주문 화면에서 회전을 고치거나 JLC 엔지니어 확인을 요청하세요.
5. Extended 부품은 19종입니다(종류마다 로딩 수수료). 재고는 2026-10-15 기준 모두 100개 이상입니다(`reports/jlc.json`).
6. **조립 레일(공정 가장자리)은 왼쪽·오른쪽에만 붙입니다.** 위쪽으로는 모듈 안테나가 6.2mm, 아래쪽으로는 J2가 약 2.3mm(도면 기준: 몸체 앞면 0.25mm + 노즐 2.0mm), J1이 0.5mm 보드 밖으로 나갑니다. 위아래 레일은 부품과 겹칩니다. 주문 화면에서 레일 위치를 지정하거나 JLC 엔지니어 확인을 요청하세요([REVIEW_LAYOUT.md](REVIEW_LAYOUT.md) 2번).

## 2. 도착 후, 전원 넣기 전

- 육안 확인: U2(TSSOP-20) 핀 사이 브리지, U6(QFN 2 × 2mm)와 U3(WSON)의 측면 필렛, C25·D5·D4 방향.
- 바닥 테스트 패드 사이 저항을 멀티미터로 잽니다. 0Ω 근처면 전원을 넣지 마세요.

  | 패드 | 정상 예상 |
  |---|---|
  | VBUS–GND | 수백 kΩ 이상(분압 저항 383k+100k, 255k+100k) |
  | 5V–GND, 5VD–GND | 수 kΩ 이상 (5VD는 탄탈 충전으로 천천히 올라감) |
  | 3V3–GND, 3V3A–GND | 수백 Ω 이상 |

## 3. 첫 전원

- 가능하면 전류계가 있는 USB 미터나 전류 제한 0.3A의 5V 전원으로 시작합니다. eFuse가 0.56–0.75A에서 제한하지만 첫 투입은 낮게 잡는 편이 안전합니다.
- 바닥 패드에서 측정합니다.

  | 패드 | 예상 |
  |---|---|
  | VBUS | 입력 그대로(4.75–5.25V) |
  | 5V | VBUS보다 수십 mV 낮음 |
  | 5VD | 5V − 0.3V 정도(쇼트키) |
  | 3V3 | 3.3V ±3% |
  | 3V3A | 3.3V ±1% |
  | EN | 3.3V(10k/1µF로 약 10ms 뒤) |
  | IO0 | 3.3V, 버튼을 누르면 0V |

- 대기 전류는 펌웨어 없이 약 50–100mA로 예상합니다. 300mA를 넘으면 바로 분리하세요.

## 4. 펌웨어

1. 버튼(IO0)을 누른 채 USB를 꽂고 놓습니다. CH340N에 DTR이 없어서 자동 다운로드 모드가 없습니다.
2. 컴퓨터에 CH340 USB 시리얼이 보여야 합니다. 안 보이면 USB D+/D−·USBLC6·CH340N 쪽을 봅니다(바닥 TX/RX 패드로 외부 USB-UART를 대신 연결할 수 있습니다).
3. 플래시합니다.

   ```sh
   export PLATFORMIO_CORE_DIR="$PWD/work/platformio"
   .venv/bin/pio run -d firmware -e lovelace-as-004 -t upload
   .venv/bin/pio run -d firmware -e lovelace-as-004 -t uploadfs
   ```

   펌웨어는 0.3.0 이상(0.3.1부터 환경 이름이 `lovelace-as-004`, 이전 `lovelace-as-003`과 같은 펌웨어)이어야 합니다. `CONFIG_MUTE_GPIO=22`가 들어가기 때문입니다. **이 값이 없는 펌웨어(0.2.x, 옛 `lovelace-as-002` 환경)로는 DAC가 뮤트된 채 남아 소리가 나지 않습니다**(XSMT 풀다운). 웹 UI 정보 화면에서 펌웨어 버전을 확인할 수 있습니다.
4. USB를 다시 꽂고(버튼 없이) 115200bps 로그에서 PSRAM 8MB, 플래시 8MB, `Mute GPIO 22 initialized`, `I2S initialized`를 확인합니다. 상태 LED가 켜져야 합니다.

## 5. 기능

- Wi-Fi: `LOVELACE-Setup` AP에 접속해 집 Wi-Fi를 설정합니다.
- 소리: AirPlay로 **좌/우 채널 테스트 음원**을 재생합니다. 왼쪽이 Tip(L), 오른쪽이 Ring(R)으로 나와야 합니다. AS-007에서 LCSC 회신대로 고친 AUX 잭 배정(A = L, D = R, B·C = GND)을 확인하는 단계입니다. 전원 넣기 전에 플러그를 꽂고 Tip–A, Ring–D, Sleeve–B·C 연속성을 재 보면 더 확실합니다. 재생 중 R10 패드(XSMT)는 3.3V여야 합니다.
- Bluetooth: 버튼 3초 → 휴대폰에서 페어링 → A2DP 재생. 48kHz 소스로 바뀔 때 팝이 없는지 들어 봅니다.
- Spotify Connect: 앱에서 장치 선택 → 재생.
- USB GND 잡음: 앰프를 연결하고 재생을 멈춘 채 볼륨을 올려 들어 봅니다. 휴대폰 충전기와 PC USB 포트에서 각각 듣고 비교합니다. PC에서만 "지직" 소리(Wi-Fi 송신 주기)가 나면 그라운드 루프입니다. 충전기 사용을 권장하거나 그라운드 루프 아이솔레이터로 대응합니다([REVIEW_LAYOUT.md](REVIEW_LAYOUT.md) 3번).

## 6. 팝과 보호 동작

- 이어폰 대신 앰프 입력을 낮은 볼륨으로 연결하고 확인합니다. ① 전원 투입, ② 재생 중 USB 분리, ③ 소스 전환, ④ OTA·설정 저장 뒤 재부팅. 재생 중 USB 분리 대책(D5/C25 홀드업)은 계산상 5–10ms를 버텨야 합니다. 오실로스코프가 있으면 5VD와 라인 출력을 함께 잡아 보세요.
- (선택) 가변 전원: 5.5V 동작, 5.9–6.0V에서 차단(OVLO 5.63–6.00V), 4.1–4.4V 아래에서 꺼짐(UVLO).
- (선택) 케이스에 넣고 Wi-Fi RSSI와 A2DP + Wi-Fi 동시 사용 시 끊김을 확인합니다.

## 7. eFuse 전류 여유 (오실로스코프 없이)

R15 5.1k는 전류 제한 0.65A(최소 0.56A)입니다. 데이터시트 피크로 계산한 부하는 5V에서 약 0.33A이므로 여유는 약 40%입니다([REVIEW_NETLIST.md](REVIEW_NETLIST.md) 2절 1번). ngspice 시뮬레이션에서는 3.3V 쪽 피크가 0.6A(4.4V 입력에서는 0.5A)를 넘을 때 처음 붕괴했습니다(4절). 여유가 부족하면 5V가 순간적으로 처집니다. 하지만 버크는 입력이 약 3.5V 이상이면 3.3V를 유지하므로, 실제로 문제가 되는 결과는 **ESP32 리셋** 하나입니다. 리셋은 보드가 스스로 기록하므로 오실로스코프 없이 판정할 수 있습니다.

**쓰는 것**
- 웹 UI 정보 화면(또는 `/api/system/info`)의 `reset_reason`과 `uptime_s`입니다. 펌웨어는 브라운아웃 감지기(약 2.43V)를 켜 둔 상태이고, 브라운아웃으로 리셋되면 원인이 `brownout`으로 나옵니다.
- 시리얼 로그(115200bps)의 `Boot: reset reason` 줄과 `Brownout detector was triggered`입니다.
- 전압 표시 USB 케이블로는 충전기 쪽 VBUS만 봅니다. 4.75V 미만이면 충전기나 케이블을 바꿉니다. 이 값은 eFuse 앞의 전압이라 보드 안쪽 처짐은 보이지 않습니다.
- 멀티미터가 있으면 각 상황에서 5V·3V3 패드의 평균값도 적습니다. 순간 처짐은 잡히지 않습니다.

**상황별 확인** (시작할 때 `uptime_s`를 적고, 끝날 때 리셋 원인과 업타임이 이어졌는지 봅니다)

| # | 상황 | 시간 | VBUS(케이블) | 리셋 원인 | 업타임 이어짐 | 소리 끊김 |
|---|---|---|---|---|---|---|
| ① | 콜드 부팅 10회(USB 뽑았다 꽂기) | 회당 30초 | | 매번 `poweron` | — | — |
| ② | Wi-Fi 연결 + AirPlay 재생 | 30분 | | | | |
| ③ | A2DP 재생 + Wi-Fi 연결 유지(공존) | 30분 | | | | |
| ④ | Spotify 재생 중 OTA 업데이트 | 1회 | | OTA 뒤 `software` | — | — |
| ⑤ | 공유기에서 먼 곳(약한 신호 = 최대 송신 출력)에서 ② 반복 | 30분 | | | | |
| ⑥ | 출력이 약한 충전기·긴 케이블(VBUS 4.8V 이하)로 ② 반복 | 30분 | | | | |

**판정**
- 통과: ①은 매번 `poweron`으로 정상 부팅합니다. ②–⑥은 업타임이 끊기지 않고, 리셋 원인이 바뀌지 않습니다.
- 실패: `brownout` 또는 예상하지 않은 리셋이 한 번이라도 나오면, 그 상황을 기록하고 먼저 비어 있는 C26(0402, U6 오른쪽 위) 자리에 1nF를 답니다. ITIMER 커패시터는 ILIM과 2 × ILIM 사이의 짧은 피크를 전류 제한 없이 통과시키는 시간을 정합니다(U6는 차단형이 아닌 전류 제한형). 데이터시트 값(방전 1.8µA, 문턱 1.51V)으로 1nF는 약 0.8ms, 10nF는 약 8ms입니다. 그래도 같으면 10nF로 올리고, 그다음에 R15를 4.3k(0402, 1%)로 바꿉니다(전류 제한 0.78A, 0.66–0.89A). 바꾼 보드로 같은 상황을 다시 확인하고, 다음 rev에서 `plan_pcb.py`의 R15 값과 `pinout_check.py`의 기대값을 함께 바꿉니다.
- 오실로스코프가 생기면 5V·3V3 패드를 함께 잡아 처짐의 깊이를 봅니다. 트리거는 5V 하강 4.6V입니다.

## 바닥 테스트 패드

`renders/latest/bare-bottom.png`에 이름과 함께 보입니다. VBUS, 5V, 5VD(+5V_DAC), 3V3(+3V3_D), 3V3A, GND, GND2, TX, RX(ESP32 쪽 UART0), EN(GND에 대면 리셋), IO0(GND에 대면 다운로드 모드 진입 조건)입니다. XSMT는 바닥에 자리가 없어 윗면 R10 패드에서 잽니다.
