# 넷리스트 독립 검토 (1단계) — 2026-10-16, AS-003 rev A에서 수행, AS-004·AS-005·AS-006 rev A에 해당, AS-007은 J2 배정만 다름(REVIEW.md 2번), AS-008은 U6 ITIMER에 미실장 C26 랜드(ITIMER 넷)만 더함

DRC·ERC·parity·Gerber netcheck는 모두 `plan_pcb.py`를 정답으로 삼습니다. 그래서 넷리스트 자체가 틀리면 전부 0으로 통과합니다. 이 검토는 **데이터시트만 보고 핀별 기대값을 먼저 적은 뒤** 넷리스트와 비교했습니다. 기대값 표는 [`pinout_check.py`](pinout_check.py)에 있고, `make_board.sh`가 배치 검사 직후 실행합니다. 하나라도 다르면 빌드가 멈춥니다.

## 2. 핀은 맞지만 확인이 필요한 것

1. **[Minor, 실측 확인 — R15 5.1k 유지, 절차는 [BRINGUP.md](BRINGUP.md) 7절] eFuse 전류 제한 여유는 약 40%입니다.** ESP32-WROVER-E 데이터시트 표 16에서 모듈 피크는 350mA입니다(802.11b 1Mbps, 19.5dBm, 송신 100% 듀티). 버크 효율을 85%로 잡으면 4.75V 입력에서 0.29A이고, DAC LDO 31mA와 CH340N·LED를 더하면 약 0.33A입니다. ILIM 최소값 0.56A보다 0.23A 낮습니다. 시뮬레이션(4절)에서는 3.3V 쪽 피크가 0.6A(5V 입력)·0.5A(4.4V 입력)까지 버텼습니다. 데이터시트 피크의 1.4–1.6배입니다. 처음 적은 0.45A는 데이터시트의 "외부 전원은 0.5A 이상 공급" 권장값을 부하로 잘못 쓴 계산이었습니다. 그 값은 공급 능력 기준이고 실제 부하가 아닙니다. Bluetooth와 Wi-Fi는 시분할이라 전류가 더해지지 않습니다. TPS259470A는 한계를 넘으면 끊지 않고 전류를 제한합니다. 그래도 버크는 입력이 약 3.5V 이상이면 3.3V를 유지하므로, 문제는 ESP32 리셋 외에 DAC 전원·출력 잡음으로도 나타날 수 있습니다. 첫 보드에서는 웹 UI의 리셋 원인과 업타임으로 이를 확인합니다. 리셋이 생기면 R15를 4.3k로 바꿉니다(0.78A, 0.66–0.89A). 다만 Rd만 있는 USB-C 기본 전원 상한(500/900mA)에 가까워집니다.
2. **[Minor] 인덕터 포화 전류 2.1A < TPS62162 전류 제한 최대 2.45A.** Murata DFE201612P-2R2M 표의 최대값은 인덕턴스 30% 감소 기준 2.1A(typ 2.3A), 온도 상승 40°C 기준 1.5A(typ 1.8A)입니다(이전 판은 둘을 뒤바꿔 적었습니다). 정상 부하(피크 약 0.6A)에서는 문제가 없습니다. 3.3V 쇼트나 과부하 때만 인덕터가 포화합니다.
3. **[Minor] 상태 LED가 어두울 수 있습니다.** `plan_pcb.py` 주석은 Vf를 약 2.9V로 적었지만, JLC 데이터의 KT-0603G는 5mA에서 Vf 3.1V(에메랄드 그린)입니다. 3.3V와 220Ω이면 약 1–2mA라 어둡게 켜집니다. 밝기가 중요하면 R18을 100Ω으로 바꿉니다.
4. **[Minor] C25 감액.** 6.3V 폴리머 탄탈은 10% 감액 기준으로 5.67V까지 권장됩니다. 평소 4.7V에서는 문제없고, 입력이 OVLO 한계 6.0V일 때만 약 5.7V가 됩니다.

## 4. 전원 경로 시뮬레이션 (ngspice, 2026-10-20 보강)

[`sim/power_path.py`](sim/power_path.py)는 USB/케이블 → eFuse → 버크/ESP32 및 D5/C25/LDO/DAC를 모델링합니다. 최신 결과는 [`reports/sim.json`](reports/sim.json), 검사 범위와 보드 검증 결과는 [VALIDATION_RESULTS.md](VALIDATION_RESULTS.md)에 있습니다.

- 기동 3조건과 0.37A 펄스 부하 6조건은 기존 기준(3V3 3.2V 이상, 전류 제한 조건)을 유지해 통과했습니다. 0.5–0.9A의 과부하 탐색 30조건은 `STRESS_ONLY`로 분리하며 전부 정상 동작했다는 뜻이 아닙니다.
- 홀드업은 입력 5.0/4.4V × ESP 80/250mA × C25 220/176µF × DAC 31/45mA = 16조건입니다. 4.4V 입력은 저전압 스트레스이고, 실제 기동 가능 여부에는 UVLO 오차도 영향을 줍니다.
- DAC 세 전원이 공통이므로 DVDD/CPVDD 권장 하한 **3.1V**를 기준으로 측정합니다. clock-stop 기준은 **3ms**, XSMT 경로는 별도로 **150/fs + 0.2ms**입니다. XSMT 파형은 모델에 없어서 `UNVERIFIED`로 남깁니다. 과거 clock-loss에 3.6ms 공식을 적용한 설명은 이 절로 대체합니다.

| 입력 / ESP 부하 | C25 / DAC 부하 | 클럭 정지 가정 후 3.1V까지 | clock-stop 판정 |
|---|---|---:|---|
| 5.0V / 80mA | 220µF / 31mA | 11.029ms | PASS |
| 5.0V / 80mA | 176µF / 45mA | 5.765ms | PASS |
| 4.4V / 80mA | 220µF / 31mA | 6.731ms | PASS |
| 4.4V / 80mA | 176µF / 45mA | 3.441ms | PASS |
| 4.4V / 250mA | 176µF / 45mA | 3.569ms | PASS |

최소 결과는 3ms 기준 대비 **0.441ms** 여유입니다. ESP32 2.43V 도달 시 I2S가 멈춘다는 가정, 이상적인 버크, LDO 고정 20mV 강하, 저항성 DAC 부하는 유지했습니다. 45mA는 25°C 데이터시트 조건이며 모든 온도의 최대값을 보장하지 않습니다. 실제 전류·클럭 정지·mute·팝·스위칭 과도응답은 미검증입니다.

**다시 돌리기:** `python3 sim/power_path.py`(PATH에 ngspice 필요). 기준 미달은 exit 1, 해석 미완료/timeout/측정 누락/수렴 오류는 `UNVERIFIED`와 exit 2입니다. 마지막 해석 시각과 모든 필수 측정값의 유한성까지 확인합니다. `make_board.sh`도 release 생성 전에 이 검사를 실행합니다. 회귀 테스트는 저장소 루트에서 `python3 -m unittest discover -s tests -p test_hardware_validation.py -v`로 실행합니다.
