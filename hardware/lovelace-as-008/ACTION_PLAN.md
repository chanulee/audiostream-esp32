# AS-008 첫 시제품 실행 계획 — 2026-10-20

**목표: 첫 시제품이 실제로 동작하는 것.** 순서는 ① 전원이 정상으로 올라온다 → ② USB로 펌웨어를 올린다 → ③ AUX로 소리가 난다 → ④ AirPlay·Spotify·Bluetooth가 된다 → ⑤ 몇 시간 재생해도 리셋되지 않는다. 팝·잡음·EMI 같은 품질 항목은 그다음이다.

## 판단

**지금 시제품을 주문한다. 검증 코드 보강은 주문을 막지 않고, 보드를 기다리는 동안 진행한다.**

[독립 스트레스 검토](../../work/independent-stress-20261020/REVIEW.md)가 찾은 것은 *검사 도구의 범위 한계*이지 설계 오류가 아니다. 검사기가 놓친 네 항목을 실제 주문 파일(`release/lovelace-as-008.d356`, `bom.csv`)에서 직접 확인했다. 모두 맞다.

| 항목 | 주문 파일의 실제 값 | 판정 |
|---|---|---|
| C25 | 220µF 탄탈(C212684), +5V_DAC–GND, 실장 | 정상 |
| C12 | 2.2µF(C12530), CAPP–CAPM, 실장 | 정상 |
| C13 | 2.2µF, VNEG–GND, 실장 | 정상 |
| C9 / C15 / C17 | 10µF(C19702), +3V3_A–GND, 실장 | 정상 |
| C26 | BOM에 없음(ITIMER, 의도적 DNP) | 정상 |
| U2 PCM5102A 20핀 | CPVDD/AVDD/DVDD = +3V3_A, FMT/DEMP/FLT/SCK = GND, XSMT·BCK·DIN·LRCK 연결 | 데이터시트와 일치 |

나머지 두 지적도 첫 보드의 동작 여부와는 다른 문제다.

- **홀드업 여유 부족(최악 조건 약 3ms)**: 재생 중 USB를 뽑을 때 *팝이 날 수 있다*는 뜻이다. 소리가 안 나는 문제는 아니다. 실물에서 재고 판단한다.
- **버크 과도응답 미검증**: TPS62162 표준 회로이고, 시뮬레이션은 도구 문제로 완주하지 못했다. 확인 방법은 실물 측정뿐이다. 문제가 생기면 증상은 ESP32 리셋이나 잡음이며, C26/R15 수정 경로가 이미 준비돼 있다(BRINGUP §7).

그래서 기존 계획의 P0-1(수동부품 검사기)·P0-2(홀드업 16조건 회귀)는 **다음 rev 전에 끝낼 작업**으로 옮긴다. 이 작업이 끝나도 지금 보드의 구리나 BOM은 바뀌지 않는다.

**첫 보드가 실제로 실패할 가능성이 높은 곳**(높은 순):

1. JLC 실장 방향·위치: U2, U4, U5, U7, C25의 회전, J2 위치 결정 핀(여유 0.125mm)
2. J2(PJ-320D) 접점 배정: 공급사 회신을 근거로 AS-007에서 고쳤지만 실물로는 확인하지 않았다.
3. 납땜 불량: U2 TSSOP 브리지, U3 WSON·U6 QFN 측면 필렛
4. 피크 전류에서 eFuse 전류 제한 → 브라운아웃 리셋
5. CH340N USB 인식(실패해도 바닥 TX/RX 패드로 우회할 수 있다)
6. D4 LED 극성: 외관 문제. 기능에는 영향이 없다.

1번은 주문 화면에서 대부분 막을 수 있다. 2~5번은 도착 후 순서대로 확인하고, 실패 시 대응을 아래에 미리 정해 둔다.

## 1단계. 주문 전 (결제까지)

### 1-1. 파일 고정
- [ ] 현재 작업 트리의 미커밋 변경(README, web_server.c, BRINGUP/REVIEW_NETLIST, jlc_check.py, tests)을 정리해 커밋한다. 주문한 파일이 어느 커밋인지 나중에 찾을 수 있어야 한다.
- [ ] release ZIP·design·PCB 해시가 아래 「검토 대상 고정」과 같은지 확인한다. 다르면 `make_board.sh`를 다시 돌리고 새 해시를 기록한다.

### 1-2. JLC 주문 화면 (실패 위험 1번을 막는 단계)
- [ ] Gerber ZIP, `bom.csv`, `cpl.csv`를 올린다. 4층, 1.6mm, 윗면만 조립.
- [ ] 3D/배치 미리보기에서 BRINGUP §1-4 표의 7개 부품 방향을 하나씩 확인한다: U2 1번 핀, U4 IN, U5·U7 1번 핀, C25 + 띠, D5 캐소드, D4.
- [ ] J2의 위치 결정 핀 2개가 보드 구멍 위에 있는지 확인한다.
- [ ] 레일은 왼쪽·오른쪽만, 폭 5mm 이상, mouse-bite로 지정한다(BRINGUP §1-6). 위아래는 안테나와 J1/J2가 튀어나온다.
- [ ] 하나라도 애매하면 JLC 엔지니어의 배치 확인을 요청한다. 며칠 늦어지는 편이 보드를 다시 주문하는 것보다 싸다.
- [ ] 결제 직전에 32종 재고를 조립 수량 + 손실분 기준으로 다시 확인한다.

### 1-3. 수량과 함께 살 부품
- [ ] **PCB 5장, 조립 3장을 권장한다.** 1장은 손대지 않는 기준 보드, 1장은 C26/R15 재작업 실험용, 1장은 납땜 불량 대비 예비다. 예산이 되면 5장 모두 조립한다.
- [ ] 재작업용 부품을 LCSC에서 같이 주문한다(몇 개씩, 저렴함): 0402 1nF·10nF(C26 자리), 0402 4.3k 1%(R15 대체), 여분 220µF 탄탈 1–2개.

**주문 조건:** 1-1과 1-2가 끝나면 주문한다. 검증 코드 보강(2-4)과 TI 모델(2-5)은 기다리지 않는다.

## 2단계. 보드를 기다리는 동안 (약 1–3주)

### 2-1. 펌웨어를 미리 준비한다 (도착 당일 막히지 않게)
- [ ] `pio run -e lovelace-as-004` 빌드와 `sh tools/test_host.sh`가 통과하는지 확인한다. firmware/version.txt는 0.3.x이고 `CONFIG_MUTE_GPIO=22`가 들어 있어야 한다(BRINGUP §4).
- [ ] 펌웨어 이미지와 SPIFFS 이미지를 미리 빌드해 둔다.
- [ ] **네트워크 없이 L/R 테스트 톤을 내는 방법**을 확인한다. 없으면 버튼 조합이나 시리얼 명령으로 1kHz 왼쪽 → 오른쪽 톤을 내는 bring-up 모드를 추가한다. 소리가 안 날 때 Wi-Fi/AirPlay 문제와 DAC/잭 문제를 바로 구분할 수 있다.
- [ ] ESP32-WROVER 개발보드와 PCM5102A 모듈이 있으면 같은 핀(BCK 21, DIN 19, LRCK 18, XSMT 22)으로 펌웨어 전체를 먼저 돌려 본다. 펌웨어 쪽 위험이 거의 사라진다.

### 2-2. 장비 준비

- [ ] 3.3V USB-UART 어댑터: CH340N이 안 될 때 바닥 TX/RX/EN/IO0 패드로 플래시하는 예비 수단
- [ ] 인두, 플럭스, 솔더윅, 핀셋: U2 브리지 수정과 0402 재작업용
- [ ] (선택) 2채널 이상 오실로스코프: 4단계 팝·전원 측정에만 필요하다. 1–3단계는 없이도 된다.

### 2-3. 문서 정정 (10분)
- [x] BRINGUP §6의 "5–10ms를 버텨야 합니다"를 *명목 조건 계산값이며, 저전압·부품 편차 조건에서는 약 3ms까지 줄어든다*로 고친다.

### 2-4. 검증 코드 보강 (기존 P0-1·P0-2; 다음 rev 전 필수, 이번 주문과는 무관)
- [x] `pinout_check.py`에 핵심 수동부품 계약 검사를 추가한다: C25, C12, C13, C9, C15, C17, 버크 입출력 C의 값·두 넷·실장 여부·극성. C26은 DNP 예외로 둔다. 기대값은 데이터시트 기준으로 직접 쓰고 `plan_pcb.py`에서 복사하지 않는다.
- [x] 독립 검토의 오류 주입 7건을 `tests/` 회귀 테스트로 옮긴다. 정상 입력은 통과하고 7건은 모두 실패해야 한다.
- [x] `sim/power_path.py`: ngspice 완주 여부와 측정값 존재를 확인한다(미완료면 `UNVERIFIED`). 16개 corner 조건을 추가하고, 공통 DAC 레일 기준 **3.1V**(PCM5102A §8.3 DVDD/CPVDD 하한)를 넣는다. XSMT 경로(150/fs + 0.2ms)와 clock-stop 경로(3ms)를 나눈다.

구현·실행 결과: [VALIDATION_RESULTS.md](VALIDATION_RESULTS.md). 주문 파일과 PCB는 변경하지 않았다.

### 2-5. (선택) TI TPS62162 스위칭 모델
PSpice 호환 환경이 있으면 80→500mA 부하 변화에서 overshoot, ripple, settling을 본다. 완주하지 못하면 `UNVERIFIED`로 두고 실물 측정으로 대신한다. 이 결과로 이번 주문을 바꾸지 않는다.

## 3단계. 보드 도착 후: 순서대로, 통과해야 다음 단계

자세한 측정값과 절차는 [BRINGUP.md](BRINGUP.md)를 따른다. 여기서는 순서, 통과 기준, 실패 시 첫 대응만 정한다. **기준 보드 1장으로 먼저 끝까지 가고**, 나머지 보드는 같은 결과가 나오는지 확인하는 데 쓴다.

| # | 단계 | 통과 기준 | 실패 시 먼저 볼 곳 |
|---|---|---|---|
| 0 | 육안 (BRINGUP §2) | U2 브리지 없음, U3/U6 필렛, C25·D5·D4 방향 | 브리지는 플럭스+솔더윅으로 수정. 방향이 틀리면 다음 단계로 가지 말 것 |
| 1 | 전원 전 저항 (§2) | VBUS/5V/5VD/3V3/3V3A–GND가 0Ω 근처가 아님 | 단락된 레일의 부품을 하나씩 확인 |
| 2 | 첫 전원, 0.3A 제한 (§3) | 5V, 5VD, 3V3 ±3%, 3V3A ±1%, EN 3.3V, 대기 50–100mA | 300mA 초과 시 즉시 분리. 레일별로 버크(U3)/LDO(U4)/eFuse(U6) 순서로 분리 판단 |
| 3 | USB 시리얼·플래시 (§4) | CH340 포트가 보임, 버튼 누르고 꽂아서 업로드 성공 | USB 미인식이면 U7/U5 방향 → 바닥 TX/RX/IO0 패드와 외부 USB-UART로 플래시 |
| 4 | 부팅 로그 (§4) | PSRAM 8MB, Flash 8MB, `Mute GPIO 22`, `I2S initialized`, LED 켜짐 | PSRAM 실패면 U1 납땜. LED만 꺼져 있으면 극성 문제(기능 무관)로 기록 |
| 5 | **소리** (§5) | 테스트 톤 또는 AirPlay에서 L→Tip, R→Ring, 재생 중 XSMT(R10) 3.3V | 아래 「소리가 안 날 때」 참고 |
| 6 | 세 소스 (§5) | AirPlay, Spotify, A2DP 재생과 소스 전환 | 펌웨어 문제로 분리. 하드웨어는 5단계에서 이미 확인됨 |
| 7 | 안정성 (§7 표 ①–⑥) | 콜드부팅 10회 정상, 30분 재생 6가지 상황에서 리셋 없음 | brownout이면 C26 1nF → 10nF → R15 4.3k 순서(재작업용 보드에서) |
| 8 | 팝·전원 품질 (§6, 오실로스코프) | 재생 중 USB 분리 시 BCK·XSMT·3V3A·LINE을 같은 시간축으로 측정, 3V3A 3.1V 도달 전 뮤트되는지 | 결과를 기록하고 4단계 판단으로 넘긴다. 첫 시제품 동작 여부의 기준은 아님 |

**1–7단계를 통과하면 "첫 시제품 동작"으로 본다.** 8단계는 제품 품질 판단용이다.

### 소리가 안 날 때 (5단계)
1. XSMT(R10 패드)가 재생 중 3.3V인가? 0V면 펌웨어 뮤트(0.3.x, GPIO22) 또는 U1 핀 문제다.
2. R11/R12의 DAC 쪽(DAC_L/DAC_R)에 신호가 있는가(멀티미터 AC 또는 이어폰을 살짝 대 보기)? 없으면 U2 방향·납땜, BCK/DIN/LRCK, U2 핀 1·8·20의 3.3V, CAPP/CAPM/VNEG(C12/C13) 순서로 확인한다.
3. R11/R12의 LINE 쪽에는 신호가 있는데 잭에서 안 나오면 **J2 접점 배정 문제**다. 플러그를 꽂고 Tip·Ring·Sleeve와 J2 패드 사이 연속성을 잰다. 배정이 틀렸으면 첫 보드는 와이어로 우회하고, 다음 AS 번호에서 J2 풋프린트 넷을 고친다.
4. 좌우만 바뀌었으면 펌웨어에서 채널을 바꿔 임시 대응할 수 있다. 근본 수정은 다음 rev에서 한다.

## 4단계. 결과로 다음 판을 결정

| 확인된 결과 | 이번 보드에서 | 다음 판(새 AS 번호 또는 rev) |
|---|---|---|
| 1–7단계 모두 통과 | 끝 | 2-4 검증 코드를 마치고, 8단계 결과만 반영 |
| 실장 방향 오류(JLC 회전) | 재작업 또는 해당 보드 폐기 | `jlc_check.py` 회전 보정 수정. 구리 변경이 없으면 rev 유지 |
| J2 접점 배정 오류 | 와이어 우회 | J2 넷 수정 → 구리 변경이므로 새 rev |
| brownout 리셋 | C26 → R15 재작업 후 재시험 | 효과가 있던 값을 `plan_pcb.py`와 `pinout_check.py`에 반영 |
| 전원 분리 팝 | 기록 | C25 용량, 조기 뮤트(VBUS 감지 → XSMT) 등 원인에 맞게 수정 |
| 리셋 없는 잡음(Wi-Fi 주기, 버크) | 5V/3V3/3V3A와 라인 출력 동시 측정 | 입출력 C, 레이아웃, 귀환 경로 수정 |
| LED 꺼짐 | 무시 | D4 회전 수정 |

PCB를 바꿀 때는 생성 원본 → 회로도/PCB → BOM/CPL → DRC/ERC → `pinout_check` + 2-4 검사 → release ZIP 순서로 다시 만들고 새 해시로 판정한다. 버전 규칙은 CLAUDE.md를 따른다(주문 후 구리 변경 = 새 rev).

**대량 발주**는 3단계 1–8 전부, 그리고 여러 장에서 반복한 결과와 열·RF·EMI·ESD 확인 뒤에 따로 판단한다. 외부 도구 점수나 시뮬레이션 PASS만으로 승인하지 않는다.
